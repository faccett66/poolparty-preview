Also sells / promotes:
- **Las Vegas Pool Party Pass** style products (assigned venue among a set — e.g. Encore Beach Club, Go Pool, Daylight, Moorea, LIV Beach — per event page copy).

### CTAs
- **Book Now** — dual patterns observed:

- **View Upcoming Events** / city & venue pickers on home.
- **Advertise here · Free offer / Contact Us** on advertise + contact.
- **Reserve Your Seat** / newsletter-ish modules appear in page chrome.

### Tech smell (public evidence only)
- **CMS:** WordPress (`wp-json`, `wp-login.php` 200, generator/Site Kit, theme path `wp-content/themes/poolparty`).
- **Builder:** Beaver Builder (`bb-plugin` / `fl-builder` class soup).
- **Commerce/events:** WooCommerce + `wp-event-manager` + custom product/event URLs; robots.txt includes WooCommerce disallow rules; Mailchimp-for-WooCommerce plugin path present.
- **Ticketing integrations (public):** SquadUp data-grabber plugin + checkout mount; Booketing outbound links. Eventbrite org page exists historically in search results; **no Eventbrite links observed on sampled home/event HTML today**.
- **Perf/cache:** Cloudflare; WP Rocket 3.23.x; long `cache-control: public, max-age=2678400` on HTML responses sampled.
- **Analytics/marketing:** GTM `GTM-W2K9KB6`; Google Site Kit; Popup Maker; Instagram Feed; Cookie Law Info; Accessibility OneTap.
- **Page weight:** Home HTML **~844 KB**; events **~907 KB**; venues **~738 KB** — heavy for a discovery surface.
- **Script density:** Home ~**108** `<script>` tags.
- **www:** `www.poolparty.com` → apex 301 (WordPress redirect) then 200.

**Backend control caveat:** Presence of SquadUp + Booketing + Woo + WP Event Manager implies ticket inventory, pricing, fulfillment, and possibly venue feeds live **outside** pure WP content. Dig does **not** assert who owns contracts, margins, or feed SLAs.

## 2) Broken / weak spots (real HTTP checks)

Checked 2026-09-15 via curl (follow redirects unless noted).

### Confirmed broken / confusing
| Check | Result | Why it matters |
|-------|--------|----------------|
| `GET /privacy-policy/` | **404** | Common legal URL pattern broken; `/privacy/` works |
| `GET /terms-and-conditions/` | **404** | Same; `/terms/` works |
| `GET /checkout/` | **302 → `/cart/`** | Empty/broken checkout path smell for Woo shoppers |
| Home `<title>` | “Pool Party in **NYC** \| …” while H2 pitches **world** guide | SEO/trust mismatch |
| `/events/` title | “Book **Las Vegas** Pool Party Events…” | Index page title over-narrow vs multi-city inventory |
| `/venues/` title | “Top Pool Party Venues in **Las Vegas**…” | Same |
| Apex security headers | No visible **HSTS / CSP / Referrer-Policy / Permissions-Policy / X-Frame-Options** on sampled `curl -I` | Weaker than Booketing’s own headers (Booketing showed XFO + Referrer-Policy) |
| `GET /wp-json/wp/v2/users` | **200** (~22 KB body) | User enumeration exposure |
| `GET /wp-login.php` | **200** | Expected for WP; attack surface remains public |
| `GET /xmlrpc.php` | **403** | Blocked (good) |

### Weak (not hard-404, but product-hurting)
- **Split booking UX:** Booketing off-site vs SquadUp overlay vs Woo cart — user cannot predict where “Book Now” lands.
- **LV Pass Book Now** opens `#ppevent` SquadUp mount (`#squadup-checkout`) — JS-dependent; no graceful non-JS ticket path observed in HTML.
- **Massive HTML** + Beaver node class noise → slow TTFB perception on mobile, harder redesign/CMS hygiene.
- **Missing/weak H1 pattern** on several key pages (home parse: no `<h1>`; long H2 SEO essays instead).
- **Generic privacy copy** (orders/marketing boilerplate) — light for a ticket reseller/promoter surface that collects phone for SMS (SquadUp order question).
- **Advertise page** now leads with “Your events. Our audience.” and routes partners through the calendar-pitch form / Contact Us.
- **Sitemap dualism:** Yoast `sitemap_index.xml` plus a separate `sitemap.xml` urlset (xml-sitemaps.com stylesheet) — possible duplicate/conflicting discovery signals.
- **Login wall:** Only for account/order depth (`/my-account/` login). Public catalog was reachable; **operator backend / feed admin not inspected**.

### What looked OK
- Core nav URLs **200**: home, events, venues, advertise, faqs, blog, contact, privacy, terms.
- Sample Booketing book link **200**.
- Sample event URLs **200**.
- HTTP→HTTPS redirect to apex works.
- robots.txt present; Yoast sitemap index present and recently touched (product/cities lastmod seen **2026-09-15**).

## 4a) Top visual / UX gaps the redesign should fix
*(For parent’s separate “new look” build — **not** built in this dig.)*

1. **Hero clarity:** Home feels like a long SEO article under a party brand; redesign needs one crisp promise + city/date search above the fold (not essay-first).
2. **City vs global honesty:** UI should be geo-smart or explicitly multi-city; stop NYC/LV title theater.
3. **Event cards:** Dense, repetitive cards; need stronger date/city/venue/DJ hierarchy, pass vs single-event labeling, and consistent price/availability cues (even if price lives downstream).
4. **Book Now predictability:** One component language for external book vs SquadUp modal; show “Continues on Booketing” / “Secure checkout” honesty.
5. **Map story:** Copy mentions a map; experience should either ship a real useful map or drop the claim.
6. **Mobile weight:** 800KB+ HTML + Beaver structure will never feel “daylife premium”; redesign must be component-light (design system, not node soup).
7. **Visual system:** Premium dayclub energy (photography, type, whitespace) vs current generic WP marketing blocks + popup/plugin chrome.
8. **Trust strip:** Missing modern trust row (refund path summary, age 21+, partner venues, support response expectation).
9. **B2B advertise:** Redesign should treat venue acquisition as a first-class funnel (short form, outcomes, examples) — not brochure copy alone.
10. **Account/cart orphans:** Hide or restyle empty Woo cart/checkout loops unless first-party checkout is real.
